# Unresolved questions

- **Launcher/model contract:** publish the jointly accepted string configuration
  and launcher-to-host/runner plan ownership, including where current manager
  admission is enforced. No second registry or unilateral payload extension.
- **Process proof/home lease:** qualify the session-record revision and kernel
  process-incarnation evidence required to complete hosted admission. The M3-S
  internal synthetic seam checks owned macOS process tuples and injected
  bound-lease metadata; it implements no external launcher schema or real lease.
  Real admission still requires the launcher record/observation revision, the
  Curator lease API release and a production observer accepting bind. The M1
  public runner instance identifier is not that proof. Exact-plan compatibility
  and successful real lease binding remain unimplemented.
- **Runner ownership verification:** the read-only identify exchange, original
  birth/wait-state snapshot and Darwin same-socket peer-PID binding are
  implemented. The internal qualification client has no command caller.
  Actual launcher and observer record-bound acceptance remains unimplemented:
  both need the authoritative immutable runner.execution member, independent
  full runner incarnation checks, and a NEW live child check begun after the
  complete valid reply, all within the original deadline. Existing closed
  records are not extended here. Legacy status is not ownership proof; an
  ownership snapshot does not prove liveness. Linux peer proof remains
  explicitly unsupported and has compilation-only coverage.
- **Remaining harness qualification:** Codex 0.164.0 synthetic no-tool turns and
  retained-session host replacement pass the disposable native protocol slice.
  Claude headless stream-json and Muse MSP still need native qualification;
  their current interface examples are schematic. Steering, interruption,
  native resume/fork, usage and PTY modes remain unqualified.
- **Authority notification:** M2 persists typed owner-only authority-required
  observations without raw questions and never answers them. Notification
  routing, question retrieval under existing custody and approval grants remain
  unimplemented; a durable observation alone is not a delivered escalation.
- **Production control security:** kernel UID checks in M1 authenticate an OS
  user, not agents sharing that user. Admit session/caller-scoped capabilities
  and cross-UID qualification before real deployment. No credential provisioning
  is part of M1.
- **Repository settings:** existing credentials remain under repository-owner
  custody. Any change requires the owner's separate decision; product
  development does not read, export or modify their values.
- **Later features:** goal.set/goal.clear and the session-scoped goal-provider
  capability name are reserved and unsupported; only a future grant holder may
  set/clear and an agent never sets its own goal. Self-request namespace/authority,
  optional goals, migration,
  detector automation, process-tree confinement, service installation and other
  platform backends remain separate work; none is activated by M1.
